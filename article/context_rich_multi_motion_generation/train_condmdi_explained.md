# train_condmdi.py — Explanation

## Training Pipeline — Step by Step

### 1. Config Loading (`main()`)
- Loads `configs/condmdi.yaml` via `misc.load_cfg()`
- If `cfg.resume` or `cfg.resume_only_weights` is set, finds the latest checkpoint and merges the previous run's config with current CLI args
- Saves the resolved config to `logs/condmdi/<exp_group>/<exp_name>/config.yaml`
- Optionally seeds everything with `L.seed_everything(cfg.seed)`

---

### 2. Dataset & DataLoader

`HumanML3DDataset` is built for both `train` and `val` splits:

- **`build_index()`**: Iterates over HumanML3D IDs for the split, filters out HumanAct12 sequences and sequences shorter than `min_motion_len` (20 frames). Stores `(npy_file, annotations)` pairs.
- **`__getitem__()`**: For each sample:
  1. Picks a random annotation (caption + timestamps) from the motion's annotations
  2. **`_get_motion()`**: Loads `pose_features` (shape `[T, 264]`), clips to annotation range, randomly shortens to a multiple of `unit_motion_len` (4), z-normalizes, then pads to `max_motion_len` (224)
  3. **`_construct_masks()`**: Builds two masks:
     - `valid_mask`: `[L]` bool — marks real (non-padded) frames
     - `obs_mask`: `[L, D]` bool — marks **observed keyframes** (the conditioning signal). Default strategy is `"keyframes"`: randomly picks 20 frames to serve as observations

Both train/val use `batch_size=1`, `num_workers=8`, `pin_memory=True`.

---

### 3. Model Initialization (`LitMDM`)

- **`MDM`**: The denoising U-Net/Transformer backbone. Uses:
  - `TextEncoder`: frozen CLIP `ViT-B/32` → linear projection to `cond_dim=512`
  - `TimestepEmbedder`: sinusoidal positional encoding → MLP for diffusion timestep `t`
  - Transformer layers with `AdaGN` (Adaptive Group Normalization) for conditioning
- **`create_diffusion()`**: Sets up Gaussian diffusion with 1000 timesteps, cosine beta schedule, predicting `x_start` (`predict_xstart=True`)

---

### 4. Logging & Callbacks

- **WandbLogger**: logs to project `"CoMo"`, watches model gradients every `summary_step=100` steps (disabled in debug mode)
- **Callbacks**:
  - `ModelCheckpoint` (x2): saves best `val/loss` and best `train/loss` checkpoints to `ckpts/`
  - `LearningRateMonitor`: logs LR per epoch
  - `RichModelSummary` + `RichProgressBar`: rich terminal output
  - `EMACallback` (decay=0.9999): exponential moving average of weights — enabled by default
  - `EarlyStopping`, `LRWarmupCallback`: disabled by default

---

### 5. Training Loop (`trainer.fit`)

Each step calls `training_step` → `compute_loss`:

1. **Unpack batch**: `motions [B,L,D]`, `lengths`, `texts`, `valid_mask [B,L]`, `obs_mask [B,L,D]`
2. **Transpose** to `[B, D, L]` format expected by the diffusion model
3. **Classifier-free guidance dropout**: with probability `uncond_prob=0.1`, randomly zeros out `obs_mask` entries (so the model learns to generate without conditioning)
4. **Sample random timestep** `t ~ Uniform(0, 999)` for each batch item
5. **`diffusion.training_losses(mdm, x0, t, model_kwargs)`**:
   - Adds noise to `motions` to get `x_t` using the forward diffusion process: `q(x_t | x_0)`
   - Runs `MDM(x_t, t, texts, obs_x0, obs_mask)` to predict denoised `x_0`
   - Computes MSE loss (+ optional FK/obs losses weighted by `loss.weights`)
6. **Backprop** with gradient clipping (`max_norm=1.0`), **AdamW** optimizer (`lr=1e-4`)
7. Logs `train/loss` to Wandb every 100 steps

Validation runs identically but without the `obs_mask` dropout.

## How Random Noise Works in Diffusion Training

### The Key Insight: The noise is known

The random noise does **not** break optimization. The trick is that the noise is generated by us, so the clean target is always known. From `training_losses` (`gaussian_diffusion.py:1135`):

```python
# Step 1: sample a known noise vector
noise = th.randn_like(x_start)           # epsilon ~ N(0, I)

# Step 2: corrupt the clean motion with it
x_t = self.q_sample(x_start, t, noise)  # x_t = sqrt(abar_t) * x0 + sqrt(1-abar_t) * epsilon

# Step 3: ask the model to predict x0 from x_t
model_output = model(x_t, t, ...)

# Step 4: compare prediction to the KNOWN clean x0
target = x_start  # because predict_xstart=True
loss = MSE(model_output, target)
```

Since we generated the noise ourselves, we always know what the target is. The model is trained to **undo** noise that we intentionally added.

### Visualizing what happens at each training step

```
Clean motion x0  ──── add noise epsilon at level t ────►  noisy motion x_t
                                                                │
                                                                ▼
                                                    MDM(x_t, t, text, keyframes)
                                                                │
                                                                ▼
                                                           predicted x0_hat
                                                                │
                                                   loss = MSE(x0_hat, x0)  ◄── known!
```

---

### Why does random `t` also work?

Each step randomly samples `t ~ Uniform(0, 999)` (`lit_mdm.py:73`). This means:
- `t=999` → motion is nearly pure noise → model learns to recover structure from chaos
- `t=1` → almost clean motion → model learns fine-grained refinement

Over many steps, the model sees **all noise levels** and learns to denoise at each one. This is called **denoising score matching** — each mini-batch trains on a different noise level, but they all converge to the same loss surface.

---

### The math behind `q_sample` (`gaussian_diffusion.py:193`)

```python
x_t = sqrt_alphas_cumprod[t] * x_start
    + sqrt_one_minus_alphas_cumprod[t] * noise
```

This is the closed-form forward diffusion formula: `x_t = sqrt(abar_t) * x0 + sqrt(1 - abar_t) * epsilon`

- At `t=0`: `abar_t ≈ 1` → `x_t ≈ x0` (almost no noise)
- At `t=999`: `abar_t ≈ 0` → `x_t ≈ epsilon` (almost pure noise)

Because this is closed-form, you can jump to **any noise level in one step** — no need to iteratively apply noise 999 times during training.

---

### Summary

| Question | Answer |
|---|---|
| Does random noise break optimization? | No — the noise is generated by us, so the clean target is always known |
| What does the model actually learn? | Given `(x_t, t, text, keyframes)`, predict the clean `x0` |
| Why is `t` also random? | To train the model at all noise levels simultaneously |
| What is the loss? | MSE between predicted `x0_hat` and the actual clean `x0` |
| Loss components | `recon_loss` + `obs_loss` (keyframe accuracy) + `fk_loss` (forward kinematics), each weight=1.0 |
